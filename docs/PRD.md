# スキマッチ（Skimatch）PRD

## 1. コンセプト
「好きと予定が合う人に、ちゃんと会える。」
外見・趣味の一致だけに頼らず、相互の希望・価値観・恋愛目的・生活時間（曜日/時間帯）・希望エリア・会話傾向を用いて、実際のデートまで無理なく進みやすい相手を提案する、18歳以上限定の音声AIコンシェルジュ型マッチングアプリ。

## 2. ターゲットユーザー
- 18歳以上、恋愛・交際を目的とした出会いを探す成人
- 「大量スワイプ」「条件検索の手間」「マッチ後に会えない」ことに疲れているユーザー
- スキマ時間（通勤・休憩等）に、タップより会話の方が早いユーザー

## 3. 主要な差別化ポイント
1. ホーム画面の主操作が「AIと話して相手を探す」（音声マッチコンシェルジュ）
2. 推薦理由を必ず提示する説明可能なマッチング（LLM単独スコアリングはしない）
3. デート後アンケート → 双方合意時のみAIセカンドデート提案、という「初回デートで終わらせない」導線
4. Warm Futurism / Human AI という視覚言語で、AIが自然に生活に溶け込む体験

## 4. MVPスコープ（Phase 1-4、詳細は docs/tasks.md）
1. メール/OTP認証
2. 18歳以上確認・利用規約/プライバシー同意
3. プロフィール作成（テキスト入力 + 音声会話のどちらでも完結可能）
4. AI音声コンシェルジュによる相手探しと理由つき候補紹介
5. 音声操作（詳細確認・条件変更・いいね・見送り・相互マッチ）
6. マッチ後のリアルタイムチャット
7. 音声メッセージ作成（自分の言葉モード／AI文案モード／声のまま送る）
8. 初回デート後の非公開アンケート（音声 or 選択式）
9. 双方合意時のみのAIセカンドデート提案
10. ブロック・通報・マッチ解除
11. 自分のデータ閲覧・退会・削除申請
12. 最低限の管理・モデレーション画面

## 5. 非スコープ（MVPに入れないもの）
- 顔の魅力度採点
- 写真・声から性格/人種/病気/収入等を推測する機能
- 完全自動でのメッセージ送信
- 「デート成功率」「交際確率」など断定的な確率表示（→「おすすめ度」0-100として提示）
- 位置情報の常時追跡・正確な位置の保存
- 課金、ライブ配信、音声通話などの大型機能
- 実データが十分に集まる前の機械学習モデルの自動学習（イベント記録のみ行う）

## 6. 成功指標（北極星指標と補助指標）
北極星: **合意された健全な初回デート提案の成立数**（滞在時間・無限スクロールは指標にしない）

MVP初期（20〜50人規模）で見るべき指標:
- プロフィール完了率
- 相互マッチ率（いいね送信 → 相互マッチ）
- 初回返信率（マッチ → 最初のメッセージへの返信）
- デート提案承認率（date_proposal_created → accepted）
- ブロック・通報率（安全シグナルとして低いほど良いが、0であることが目的化しないよう注視）

これらが一定件数集まってから、docs/tasks.md記載のスコア重みを調整する。件数が少ない段階でのML自動学習は行わない。

## 7. クリティカルな不明点と意思決定
着手前に確認すべき5点に絞り、それ以外は仮定として明文化した（詳細はdocs/architecture.md「前提・仮定」）。

| # | 論点 | 状態 |
|---|---|---|
| 1 | 実Supabaseプロジェクトの有無 | 未提供 → モックアダプタを既定とし、環境変数投入で実接続に切替可能な構成を採用（仮定） |
| 2 | 本番AIプロバイダ（STT/LLM/TTS）の選定 | 未指定 → server-only adapterで交換可能にし、既定はモックプロバイダ（仮定） |
| 3 | 年齢確認の厳密度（自己申告か公的書類か） | 未指定 → MVPは生年月日自己申告+チェックボックス同意、公的書類確認は将来拡張として設計のみ残す（仮定） |
| 4 | Phase1の検証対象プラットフォーム | コンテナ内にiOS/Androidシミュレータ不在 → Expo Web + `tsc`/lint/testで検証し、実機/シミュレータ確認はREADMEに手順のみ記載（仮定） |
| 5 | 決済・収益化 | 指示に明記なし → MVP非スコープとして扱う（仮定） |

上記はいずれも致命的にブロックする論点ではないため、ユーザーへの質問はせず仮定として進行した。方針変更があれば都度ドキュメントを更新する。

## 8. 主要ユーザーフロー（MVP）
1. 起動 → メール/OTP認証 → 18+確認・同意 → プロフィール作成（テキスト or 音声）
2. ホーム（AIオーブ）→「今日はどんな人と話してみたいですか？」→ 音声で希望を話す
3. AIが条件チップを提示 → 「この条件で探す」確認 → 候補を1人ずつ紹介
4. 音声/タップで「もっと詳しく」「次の人」「いいね」「見送り」「条件を変える」
5. 相互いいね成立 → マッチ → チャット（音声メッセージ含む）
6. 初回デート後、非公開アンケート → 双方「また会いたい」の場合のみAIセカンドデート提案
7. 3案から選択・投票 → 双方合意で日程確定

## 9. リスクと軽減策
- **誤った推測によるプロフィール差別化リスク**: 声質・写真・返信速度から属性推測を行わないことをアーキテクチャ・プロンプト双方でハード制約化
- **AIの暴走（自動送信・条件緩和）**: 重要操作は必ず確認ダイアログを挟む設計を全AI機能で徹底
- **音声データの過剰保持**: 既定は文字起こし後に生音声を削除、保存は本人選択時のみ・期限付き
- **コールドスタート**: 明示条件と質問回答を優先し、探索枠は小さく設定、人気度だけで有利にしない
